# EyeMyHealth MCP tool reference

_Generated by `npm run mcp:docs` from the live tool registry - do not edit by hand._

74 tools. Every tool except `list_profiles` and `get_family_dashboard` also accepts an optional `profileId` (from `list_profiles`) to act for a family profile.

## `health:read` (47)

Read-only. Nothing is changed.

| Tool | What it does | Arguments |
| --- | --- | --- |
| `list_profiles` | List the people this account can look at: the user themself plus any family members they look after. | - |
| `get_latest_report` | Get the user's most recent uploaded health report, optionally filtered by report type. | reportType |
| `get_report_by_id` | Get full detail (measurements, summary, dates) for one of the user's reports by its ID. | **reportId** |
| `compare_reports` | Deterministically compare shared canonical parameters between two of the user's reports. | **reportIdA**, **reportIdB** |
| `get_measurement_trend` | Get the user's confirmed measurement history for one canonical parameter (by code, e.g. "hba1c", "hemoglobin"), with deterministic min/max/average/direction already calculated. | **parameterCode**, range |
| `find_measurements_in_date_range` | Find the user's confirmed measurements within a date range, optionally filtered to one parameter. | parameterCode, **dateFrom**, **dateTo** |
| `get_highest_or_lowest_in_range` | Get the user's highest or lowest confirmed value for a parameter within a date range, with its source. | **parameterCode**, **dateFrom**, **dateTo**, **direction** |
| `search_reports` | Search the user's reports by filename or measurement/test name keyword. | **keyword** |
| `explain_insight` | Get the full evidence-backed explanation behind one of the user's AI insights/alerts, by its ID. | **insightId** |
| `list_active_insights` | List the user's current active AI insights/alerts (things flagged as worth attention). | - |
| `list_medications` | List the user's tracked medications/prescriptions (from scanned or manually entered records), optionally filtered by status. | status |
| `get_medication_detail` | Get full detail for one of the user's medications by its id: what it's for, its active ingredient(s)/composition (from the curated drug reference, plus whatever was literally read off the user's own scanned label/prescription if available), common side effects and safety warnings, dose-adequacy vs. a typical daily dose, and every lab parameter it's linked to with a standards-based (WHO/ICMR/FDA - never a lab report's own printed range) in-range status, the user's latest confirmed result for it, and a forecast of when improvement is expected given how long the medication has been taken. | **medicationId** |
| `list_medication_alerts` | List the user's current active medication alerts: expiring/expired medication, an ending/completed course, or an estimated refill running low. | - |
| `get_water_summary` | Today's (or a given date's) water intake: entries, total in ml, the personal min/ideal/max target and, for today, an under/over-hydration alert. | date |
| `get_water_history` | Daily water totals (ml) for the last N days (1-90, default 14) with the current target. | days |
| `get_health_profile` | The person's height, weight history, BMI and recorded allergies. | - |
| `get_weight_goal` | The person's weight goal: current weight, target weight and target date. | - |
| `list_kitchen_items` | Items in the person's kitchen/pantry that recipe and meal suggestions draw on. | category, search, availableOnly |
| `get_medication_reminders` | Today's (or a given date's) medicine doses: what is due, taken, skipped, and recently missed. | date |
| `get_privacy_consents` | Which privacy choices this person has made (record storage, AI document reading, AI insights, AI apps). | - |
| `list_retest_plans` | Retest Radar: for each out-of-range result (and medicines linked to a lab value), the date to check again by, its status and a booking link. | - |
| `get_insurance_overview` | Health-insurance policies on file with insurer, cover period, premium and renewal dates, and which lab results each policy covers or doesn't (coverage gaps). | - |
| `get_insurance_summary` | A short insurance summary: number of policies, upcoming premium/renewal dates and coverage gaps raised by out-of-range results. | - |
| `get_insurance_policy` | Full detail for one insurance policy by id: contacts, premium schedule and organ-wise clauses with ceilings, co-pay and waiting periods. | **policyId** |
| `get_diet_summary` | Calories and nutrients per day for the last N days (1-90, default 7), grouped by meal, plus how many logged meals still need review. | days |
| `list_food_entries` | Logged meals/foods with calories and nutrients. | date, from, to, unconfirmed |
| `get_diet_recommendations` | Pattern analysis of recent eating with practical tips that take the person's confirmed lab results and active medicines into account. | days |
| `list_diet_schedules` | Meal plans (diet schedules) the person has created or imported, newest first. | - |
| `get_diet_schedule` | One meal plan with every day's meals by id. | **scheduleId** |
| `list_workouts` | Recent AI-coached workout sessions (newest first) with exercise, reps/duration and estimated calories. | limit |
| `get_workout_summary` | Detailed summary of one workout session by id: sets, reps, form feedback, fatigue and comparison with the previous session. | **workoutId** |
| `get_workout_analytics` | Workout totals and trends across all completed sessions (frequency, volume, best efforts). | - |
| `get_exercise_progression` | How performance on one exercise has changed over time. | **exerciseId** |
| `list_exercises` | The exercises the AI workout coach can track, with their ids. | - |
| `list_workout_plans` | The person's saved workout plans. | - |
| `get_workout_plan` | One saved workout plan with its exercises, by id. | **planId** |
| `get_activity_summary` | Steps, exercise minutes, stand hours, calories burned and ring progress for today and the last N days (1-90, default 14). | days |
| `get_glucose_summary` | Glucometer readings by day (average/min/max, time in range) compared with the latest lab fasting glucose, post-prandial glucose and HbA1c. | days |
| `get_vitals_summary` | Latest readings from paired devices: blood pressure, heart rate, SpO2, temperature, weight and similar. | - |
| `get_vitals_history` | History of one vital sign over the last N days. | **readingType**, days |
| `list_devices` | Health devices (BLE monitors, wearables) paired to this profile. | - |
| `get_dashboard_snapshot` | The person's dashboard: pinned metrics with latest and previous values, results that need attention (latest out-of-range or awaiting review), and active insights. | - |
| `get_organ_health` | One card per body organ group (liver, kidney, heart, blood, thyroid, diabetes ...): how many of its latest results are in range and which are high or low, judged by the lab's own range or a standard reference range. | - |
| `get_needs_attention` | Only the latest results per test that are out of range or still need review, with the report each came from. | - |
| `list_timeline` | Chronological list of reports, newest first, with abnormal-result counts and summaries. | dateFrom, dateTo, reportType, source, category, search |
| `search` | Search the person's own EyeMyHealth records - reports (by file name, test name or summary), insights and medicines - for a keyword or phrase. | **query** |
| `fetch` | Get the full content of one item returned by `search` (a report with its results, an insight with its evidence, or a medicine), by its id. | **id** |

## `health:log` (7)

Everyday "log this" actions. Additive and easy to correct.

| Tool | What it does | Arguments |
| --- | --- | --- |
| `log_water` | Log a drink of water in millilitres (e.g. 250 for a glass). | **amountMl**, loggedAt |
| `log_meal` | Log something the person ate or drank. | **name**, mealType, consumedAt, calories, proteinG, carbsG, fatG, notes |
| `log_medication_dose` | Mark one scheduled dose as taken or skipped, or undo it. `slot` is one of the medicine's scheduled times from get_medication_reminders (e.g. "morning"). | **medicationId**, **slot**, **status**, date |
| `log_weight` | Record a body-weight measurement in kilograms. | **weightKg** |
| `log_height` | Record body height in centimetres. | **heightCm** |
| `log_activity` | Log a day's steps, exercise minutes and/or stand hours. | date, steps, exerciseMinutes, standHours |
| `retest_checkin` | Tick (or untick with done=false) this week's small action on a Retest Radar plan. | **planId**, done |

## `health:write` (19)

Edits, uploads and permanent deletes. Deletes are two-step (see the Safety section).

| Tool | What it does | Arguments |
| --- | --- | --- |
| `snooze_retest` | Push a Retest Radar reminder out by 1-60 days. | **planId**, days |
| `dismiss_retest` | Dismiss a Retest Radar plan the person no longer wants to be reminded about. | **planId** |
| `dismiss_insight` | Dismiss an insight so it stops showing (it can reappear if the underlying results change). | **insightId** |
| `rate_insight` | Record whether an insight was useful or not useful. | **insightId**, **feedback** |
| `dismiss_medication_alert` | Dismiss a medication alert (expiring, refill needed, course ending). | **alertId** |
| `add_allergy` | Add an allergy (e.g. "peanuts", "penicillin") to the health profile. | **allergen** |
| `set_weight_goal` | Set or replace the weight goal. | currentWeightKg, targetWeightKg, targetDate |
| `upsert_kitchen_item` | Add an item to the kitchen/pantry list, or update it if the name already exists. | **name**, **category**, quantityAmount, quantityUnit, isAvailable |
| `delete_report` _(permanent, two-step)_ | Permanently delete a health report (the uploaded file and every result extracted from it). | **reportId**, confirmationToken |
| `delete_insurance_policy` _(permanent, two-step)_ | Permanently delete an insurance policy (the uploaded file and its coverage clauses). | **policyId**, confirmationToken |
| `delete_medication` _(permanent, two-step)_ | Permanently delete a medicine and its dose history. | **medicationId**, confirmationToken |
| `delete_food_entry` _(permanent, two-step)_ | Permanently delete a logged meal. | **entryId**, confirmationToken |
| `delete_water_entry` _(permanent, two-step)_ | Permanently delete a logged water entry. | **entryId**, confirmationToken |
| `remove_allergy` _(permanent, two-step)_ | Permanently delete an allergy from the health profile. | **allergyId**, confirmationToken |
| `delete_kitchen_item` _(permanent, two-step)_ | Permanently delete a kitchen/pantry item. | **itemId**, confirmationToken |
| `delete_diet_schedule` _(permanent, two-step)_ | Permanently delete a meal plan and all its days. | **scheduleId**, confirmationToken |
| `delete_workout_plan` _(permanent, two-step)_ | Permanently delete a saved workout plan. | **planId**, confirmationToken |
| `delete_workout` _(permanent, two-step)_ | Permanently delete a workout session (including any retained video). | **workoutId**, confirmationToken |
| `create_upload_link` | Get a one-time link where the user can upload a file (lab report, insurance policy, meal photo, diet plan) into EyeMyHealth. | category |
